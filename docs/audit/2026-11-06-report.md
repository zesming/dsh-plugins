### 4.1 代码实现

#### [F-01]（CD-01，S1）turnTail 槽位 owner 入参契约已变，RecapTail 在新版宿主恒渲染为空
- 位置：packages/dsh-session-assist/src/ui/recap.js:61-117；packages/dsh-session-assist/src/client.js:44-52
- 现象与依据：宿主 `@deepseek-ai/dsh-client-ui-chat` 9028-9033 以 `renderSlot("conversation.chat.turnTail", { turn: <turn号>, seq: <finalNode.seq>, openFile })` 渲染，`turn` 是数字；组件却读 `turn?.end`/`turn?.turn`/`turn?.data?.get(RECAP_KIND)`，全部 undefined → identity=null → `recapPresentation` 返回 null，无报错。Definition 值（RECAP_KIND，由本插件 uiConversation.events.register 产出）官方读取方式是注册 keyedHooks：`ctx.uiConversation.binding(binding).target('chat').getSnapshot().nodes.turnDataSource(Number(turn), KEY)`（dsh-client-ui-plan 同款用法，774-788 行）。注意槽位 `seq` 是最后 assistant/message 节点 seq，不是 turn/end 事件 seq，不能当作 endSeq；turn.end.seq 仍需从 useChat 的 `timeline.turns.get(turn号).end.seq` 取。
- 影响：智能回顾在新版客户端完全不可见；Host 仍生成落盘，白耗 LLM。
- 修复建议：client.js turnTail 注册改为 inject(sessionId) 返回 `keyedHooks: { recapFacts: t => chat.nodes.turnDataSource(Number(t), RECAP_KIND) }`（binding 经 ctx.sessions.binding）；RecapTail 以 turn 号 + useChat 取富 Turn（end.seq/reason/status），以 useRecapFacts(带 selector) 取 Definition value；保持原有 loading/none/ready 与 identity 校验逻辑。
